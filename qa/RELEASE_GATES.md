# Release gates and evidence rules

## Current result

No DealerSource implementation exists at the inspected commit. Application behavior is NOT_IMPLEMENTED; controlled integrations and manual checks are NOT_RUN. Successful harness/fixture checks do not alter that status.

## Gates

| Gate | Required evidence | Blockers |
| --- | --- | --- |
| Test package usable | Catalog traceability, fixture integrity, harness checks and clean-extraction rerun | Broken runner, contradictory fixtures, missing procedures |
| Offline implementation | Real reviewed application bindings, required contracts, state/race tests, no live effects | Missing bindings, fabricated expected-answer adapter, security/policy failures |
| Read-only pilot | Approved source access and exact area; real coverage/error/freshness evidence | Imaginary APIs, incomplete rights, unmeasured small/shared-space coverage |
| Shadow verification | Local previews, model error analysis, grounded questions and correct authority | Real sends/forms, invented approvals, prompt-controlled dispatch |
| Capped live pilot | Explicit PM approval of account, sender, contacts, domains, templates, caps, timing, retention and cost | Uncertain side effects, missing permissions, lost opt-outs or recovery gaps |
| Acceptance/release | Complete applicable AC evidence, locked evaluation, backup/restore and incident results, PM decision | Any critical false verification, unauthorized send, wrong-space claim, unresolved required checks |
| Ongoing operation | Fresh audits, drift monitoring, source/permission renewal and bounded change review | Treating old acceptance evidence as universal or permanently valid |

P0 means critical correctness or safety; P1 means required functional or operating behavior. Neither means a failed requirement can be silently ignored. PM-approved scope changes must be recorded and cannot waive applicable legal approval or fabricate verification.

## Statistical evaluation

The delivered fixtures are public development data. They are not independently collected real-property truth and are not a locked holdout. Later build a separate benchmark with a PM-approved sampling plan and independently adjudicated evidence. Include negative, ambiguous, stale and shared-space cases. Preserve unresolved truth cases in reporting.

Report per-field and per-status results with denominators, sample sizes, error categories and confidence intervals when statistically appropriate. Do not pool missing implementations into a passing percentage or claim all-market recall. Report model bad proposals separately from deterministic containment.

The master specification proposes 95% critical-field correctness and zero observed critical false-verification errors in an acceptance sample. These are not achieved results or a sample-size-independent guarantee. The PM must approve operational thresholds and statistical criteria before the locked set is consumed. Do not tune on locked outcomes and then claim a fresh validation.

## Required saved evidence for a real test run

- Actual implementation and configuration revision; source/license/rule snapshots.
- Commands, environment, fixtures or permitted source IDs and execution timestamps.
- Expected and actual behavior, all failures, skipped/unimplemented cases and their reasons.
- Effect ledger for controlled email/forms and proof that unauthorized effects did not occur.
- Measured costs and counts, estimated figures labeled, unavailable figures explicitly UNAVAILABLE.
- Reviewer, PM permissions and release decision separate from the developer's recommendation.

## Source and cost restrictions

Keep new paid services and overages off by default. Max is not model API credit; existing Gmail is not a free replacement mailbox. Public records, map data, tiles and geocoding are different services with different rights/limits. Do not claim free software makes hardware, hosting, administration, source rights or formal due diligence free.

Do not send an email, create a Gmail draft, fill/submit an official form, connect an account, buy data or start a recurring job just to make this suite pass. Those need their explicit phase approval.
